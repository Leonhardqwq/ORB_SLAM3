# 处理局部预算与关键帧判据的耦合

v2 的 18 次回放已完成：局部预算实际生效，定位保持良好，但 V101 关键帧从 32–34 增至 232–245，V102 从 95–102 增至 354–448，后台耗时和 CPU 增大；模式模型窗口预测校准差达 25–43 个百分点。不能接受 E4，也不继续盲目压低前端特征预算。

本轮检验具体机制：原 `NeedNewKeyFrame` 把当前内点与完整参考关键帧的可跟踪点数相比。可选工作集合缩小后，该比较可能频繁触发建图。尚不能说这已是唯一实测根因，所以同时增加逐帧判据记录。

定义参考点槽集合 R 为原参考关键帧中有效且观察数达到原 `nMinObs` 的槽；W 为当前局部候选、上一帧关联点、当前帧关联点的并集。预算一致候选使用 `#(R∩W)` 作为比较分母。保留上一帧关联，即使本轮失配也不从分母自动删掉；不把分母设置成当前内点数。不改变原 0.75 等比例、近点补充条件、时间条件、重定位及跟踪失败保护。此规则是待验证的算法启发式，不宣称已经证明质量不变或严格独立。

实现作为 `SetFixedWorkPolicy` 第四个可选布尔参数，默认 false；仅对 fixed owner T 调用生效。`--work-control 2` 保留旧预算判据，`3` 启用新判据，两组都记录 raw/eligible/used 参考数、内点、近点数量和条件位。原生默认功能、完整地图、回环/GBA 保留。计数、集合与比较成本全部计时，不将被诱发的长任务当作测量错误。

条件位：1=max-frame 条件，2=min-frame 且建图就绪，4=弱跟踪条件，8=原参考比例触发，16=预算内比例触发，32=近点条件，64=实际 c2，128=内点数大于15。早退未到该判据的行保持零；条件位不等于已创建关键帧，实际创建仍与后端记录对照。

验收顺序：

1. 同一新库完整构建，各入口、固定/原生生命周期、线程/阶段/非法参数检查通过。
2. 两条已有开发视频，每组 3 次完整进程，共 12 次 / 19,200 帧；固定分块随机顺序、种子和全部原参数，串行运行，不与 v2 混算。
3. 每行检查 `0 ≤ eligible ≤ raw` 和 used 分母与开关一致，配额和整数纳秒递推通过；保留全部质量失败和实际慢帧。
4. 检查原比例触发而预算内比例不触发的帧、真实关键帧数量及后端变化；近点条件单列。若没有预期变化，记录机制不获支持，而非继续调阈值。
5. 沿用 block 1 拟合、block 2/3 检查；10% 历史筛查和 V102 ATE 0.15 m 不改。新增每轮实际关键帧判据只作解释量，不当作事先模式。
6. 通过开发筛查也不自动接受 E4。用户已选择限定场景近似适用，最终仍需候选冻结、独立输入及预定可靠度误差/定位验收。原始失败不覆盖；此轮仅改软件，不改原理论、Lean 或组会，无 Git 暂存提交。
