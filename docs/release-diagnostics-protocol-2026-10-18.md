# 释放时序与共用负载诊断协议

2026-10-18。用户授权按上一轮方案开始诊断。本批冻结配置见[参数文件](release-diagnostics-protocol-2026-10-18.json)，沿用[原实用性协议](fixed-usability-protocol.md)的图、服务时长、100 微秒模型误差门槛、50 毫秒任务截止和质量/资源标准。旧失败不改判，本批不拟合模式或联合分布，不开展可靠度预测。

## 要区分的问题

1. 固定模式的额外启动间隙，发生在调用等待函数之前、休眠返回、主动检查，还是等待结束后的调用准备？
2. 若主动检查期间出现长间隙，能否取得线程被切换的直接计数证据？计数能定位到一个测量区间，不能重建完整内核调度链。
3. 伴随任务变慢是否可重复地关联某一策略，还是它单独运行时也出现相近变化？本批不宣称仅凭配对比较获得因果证明。

## 最小插桩与范围

只修改独立 `stereo_fixed_replay` 应用及其运行工具。`System`、Tracking、LocalMapping、视觉算法、核心动态库、原生入口及传感器功能不改动。现有构建、数据、历史产物只读复用；诊断二进制写入新目录。不设 CPU 亲和性或实时优先级，不改内核权限。

新增 `--release-diagnostics`，默认 0：

- 0：关闭新增诊断，原等待逻辑保留。
- 1：记录等待入口、休眠返回、主动检查开始/退出、探针结束，以及主动检查中相邻时钟读取的最大间隔。
- 2：另在主动检查前后读取当前线程 CPU 时间及自愿/非自愿上下文切换计数；其系统调用开销单列，仍计入模型误差。

新增原始文件 `replay-release.csv`；原有 `replay-events.csv` 的阶段定义不改。`aT` 仍为回放应用调用跟踪前的边界，没有将它改成函数内部某处。逐帧观测完成后写文件，不在释放到调用的路径中做文件 I/O。初始化记录不冒充评估帧。

令上一建图完成与本轮释放的较晚者为 (r)，等待入口、休眠返回、主动检查退出和原有跟踪调用边界分别为 (a,b,c,d)。按

\[
d-r=[\max(r,a)-r]+[\max(r,b)-\max(r,a)]
     +[\max(r,c)-\max(r,b)]+[d-\max(r,c)]
\]

逐项分解，覆盖积压后立即执行的情况。每行检查时间先后和分解精确相加；非负间隙不被扣除、归零或并入服务耗时。窗口累计模型误差继续使用原论文 `Model.step` 计算，不能以单帧启动间隙取代。

## 冻结运行安排

保持 V1_01_easy、起始帧 800、初始化最多 100 帧、评估 800 帧、20 Hz、H=20、单线程应用政策、500 微秒主动检查上限不变。

1. 三档短回放，每档评估 2 帧，检查参数、事件覆盖和诊断分解。
2. 时间戳批次：原生同范围、固定普通休眠、固定 500 微秒主动检查，分别在空闲/共用负载下各运行 3 次，共 18 次。每组策略顺序轮换，串行计时。所有运行使用诊断档 1。
3. 每次共用负载回放前后，各运行一次 20 秒的独立伴随任务，共 18 次基准。共用时仍采用20 Hz高斯滤波加ORB，图像取相同序列第800帧，与上一批一致。分析只取与SLAM评估时段重叠的共用样本。
4. 线程计数批次：固定 500 微秒策略、空闲负载、诊断档 2，共 3 次。与时间戳批次单列，不混算开销或验收结果。

伴随任务同时报告总完成时延、唤醒等待、实际计算时间。旧固定门槛 5.1950864 ms 保留；新配对诊断另外分别检查共用 p95 是否不超过前、后各自 p95 的 1.2 倍加 0.2 ms，必须两侧均满足。不得事后挑选较有利的一侧。该比较改善局部对照，不给出统计显著性承诺。20 秒基准与40秒评估的样本量不同，分别报告。

不因某次时序或质量失败中止收集其余预定对照；程序/输入错误另记并修复。任何参数探索或移动调用准备代码均需另开版本和批次。当前批次不先扩大主动等待预算。

## 证据边界与验收

- 三档入口运行成功、事件完整，逐行分解完全一致；时间倒序样例必须拒绝。
- 原模型检查仍用 100 微秒累计误差、原始调用边界和固定窗口；保留每次通过/失败、原质量与资源条件。
- 超限按实测分量定位。长时钟间隔本身不能证明线程被抢占；模式 2 的非自愿切换增量是区间内发生切换的证据，不是每一微秒延迟的归因。
- 增加探针会改变执行时序，模式 1/2 为诊断证据，不能替代关闭新增探针后的工程验收。样本未复现旧异常时，不能据此认定旧异常已消失。
- 不保证普通 WSL2 的最坏调度时延，不改宿主系统设置。本轮只报告 WSL 实测，不宣称车辆、多场景或多传感器验证。
- 保存源码、协议、命令、输入/产物哈希与分阶段日志；旧构建/结果与 Git 索引保持不变。

## 可重跑入口

`tools/build_release_diagnostics.py` 接收 `--existing-work`（已有 Ninja 构建及 `source/`）、`--output`（必须为新目录）、`--driver`（本仓库回放源码）。只重新编译回放，不重编核心或共享依赖。新 `source/` 通过符号链接只读复用旧依赖，因此搬迁归档时需保留构建清单及依赖位置。

`tools/run_release_diagnostics.py` 接收 `--phase smoke|timeline|context`、`--source`、`--data`、`--output`（各阶段必须为新目录）、`--protocol`、`--companion`、`--support-tools`。这里 `--support-tools` 为本仓库 `tools/`；`--companion` 为已有 `opencv_companion` 程序。

`tools/analyze_release_diagnostics.py` 接收 `--batch`、`--data`、`--reference`（原论文 `experiments/periodic-feedback/src/evaluate.py`）、`--support-tools` 和 `--output`（必须为新文件）。运行环境为已建立的 WSL Ubuntu；不新增安装依赖。机器专属命令及原始产物位置随结果报告保存。

## 针对调用准备异常追加的独立对照

时间戳批次 `idle-2-fixed_hybrid` 的 k=466 出现104.897微秒探针后调用间隙后，另行冻结 `release-dispatch-protocol-2026-10-18.json`。不改动已运行批次的驱动，独立编译候选，并用同一候选二进制交替比较 `--prepare-before-wait 0/1`，各三次800帧空闲回放。先完成既定的时间戳与线程计数批次，再编译和运行候选，避免编译负载干扰计时。

候选将记录初始化和调用前分支放到等待之前，实际跟踪边界、释放与服务定义保持不变；该选项默认0，只允许在instrument入口启用。三次开关对照不等于关闭诊断后的完整验收，也不替代共用负载或多场景验证。使用 `tools/run_dispatch_preparation_check.py`，传入 `--source`、`--data`、`--output`、`--protocol`（追加协议）、`--base-protocol`（本批基础协议）和 `--support-tools`；随后用原分析入口核验。

第一批源代码与最终可选开关版本的差异保存于 `release-dispatch-preparation.patch`。精确复现第一批时，在独立源码副本中反向应用该补丁后构建；不要在有用户修改的权威工作区执行反向应用。两批源码/二进制哈希分别记录。

本批文件采用CRLF行尾，GNU patch还原时使用 `--binary --reverse -p1`，避免默认剥离补丁CR导致不匹配。已在独立副本中还原并比对首批源码/运行脚本哈希；Git改写行尾后的文本等价不等于字节哈希相同。
