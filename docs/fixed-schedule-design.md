## 1. 首轮范围

选择非惯性双目、单个 System、单个调用线程、关闭 Viewer、关闭闭环/地图合并/GBA、禁用交互单步与运行中定位模式切换。保留跟踪、关键帧选择、完整局部建图、地图反馈与重定位数据库。启动时建新地图，不加载外部 Atlas；评估期间不由其他线程调用 Reset、ChangeDataset 或导出地图。

固定模式首先使用针孔双目；鱼眼、RGB-D、单目、惯性输入明确报不支持。正常的视觉跟踪失败仍记录，不能通过只接受成功帧来保证范围成立。初始化和运行中地图恢复的规则见第 4 节。

配置计划：`Execution.mode = native_async | fixed_stereo`，默认 `native_async`。固定模式要求 `loopClosing=0`、`bUseViewer=false`，检查完成后才创建工作线程。未识别模式、冲突配置、非单调图像时间戳均在启动或输入检查时明确拒绝，不自动降级为另一方法。

## 3. 图、接口与执行顺序

取模块 `T=1, B=2`，`L=1`，输出 `o=T`，边集

\[
E=\{(B,T,1),(T,B,0)\},\qquad
t_T(k)=S_T(k)+\max\{kh,t_B(k-1)\},\quad
t_B(k)=S_B(k)+t_T(k).
\]

同轮 T 到 B、跨轮 B 到 T 保证只有一个任务占用协调执行路径；不需要额外假定动态抢锁顺序。建图反馈仍是 T 读取上一轮完成的地图。B 没有关键帧时只做队列检查与完成确认，测量真实耗时，不能填零。

拟实现接口及约束：

| 接口 | 职责 |
|---|---|
| `System::ExecutionMode` 与构造参数/配置解析 | 选择模式；初始化线程指针；在线程启动前检查组合 |
| `System::TrackStereoFixed(round_id, images, sensor_timestamp)` | 前一 B 已结束才允许调用；返回含位姿、有效性及输出时刻的结果；禁止与旧 TrackStereo 混用 |
| `System::CompleteMappingRound(round_id)` | 只接受刚完成 T 的轮号；完整处理本轮队列；只能调用一次；结束前不能开始下一 T |
| `LocalMapping::ProcessOneKeyFrame()` | 从 Run 提取完整算法块；异步循环与固定入口共用；保留原分支、优化中止和剔除次序 |
| `LocalMapping::ProcessRound(round_id)` | 冻结本轮投递清单并处理；检查来源帧号、队列计数、重复 ID；输出处理清单 |
| mapper/loop closer 的 `ResetSynchronously`、`ResetActiveMapSynchronously` | 复用原清理内容，无等待已取消的 worker；仅允许协调线程安全点执行 |
| 数据库维护函数 `RegisterKeyFrameWithoutLoopDetection` | 完成 B 后对符合原入口规则的关键帧添加数据库一次；关闭识别仍保留重定位能力 |
| `System::ShutdownFixed()` | 完成本轮 B 或记录明确错误；不等待不存在的线程；确认无工作写入后导出 |

使用两段调用，不能把 B 放进 TrackStereoFixed 的返回之前：

```text
确认上轮 CompleteMappingRound 已成功
等待预先登记的 release[k]（不改写 release[k+1]）
result = TrackStereoFixed(k, left[k], right[k], sensor_timestamp[k])
发布/记录 result 和跟踪输出时间              // 此处为 t_T(k)
CompleteMappingRound(k)                     // 此后才得到 t_B(k)
```

状态机：`Ready(k) -> Tracking(k) -> NeedsMapping(k) -> Mapping(k) -> Ready(k+1)`；轮号不匹配、重复 B、漏 B、其他线程进入均报错。关闭请求只由协调线程在边界受理。实际输出交给预分配缓冲，不能让外部任意 callback 在 T 与 B 之间阻塞。

不得无条件强制插入关键帧。固定图的节点是每轮任务槽，槽内是否出现关键帧由原视觉逻辑决定。`source_frame_id -> round_id -> processed_keyframe_ids` 单独记录，ORB 内部帧号可能因 reset 改变，不能代替本次运行递增的 round_id。

## 4. 初始化、队列、重置与退出

1. 启动阶段顺序执行完整 T/B，首次初始化成功且该轮队列处理完后，才能建立评估起点；设定初始化最长帧数并记录所有未初始化运行。初始化成功后开始评估是条件化研究对象，不代表全程成功率。先完成 B 再设时间原点，可给定零剩余历史；已有地图及起始帧仍须保存。
2. 非惯性双目初次初始化创建一个关键帧，正常轮次通常零或一个。实现按有限清单处理，不以“至多一个”硬编码，不套用单目初始化的两关键帧路径。处理前后的数量和 ID 必须守恒，插入、处理、因明确 reset 失效分别记录。
3. 新关键帧仍由原创建路径拥有/登记。B 只转交和处理，不用 Release 删除队列；异常时不无依据 delete 已进入 Atlas 的指针。析构/清理遵守原地图所有权。数据库记录去重以地图生命周期与关键帧身份为键，reset 时清空相应记录，避免帧号重用冲突。
4. Tracking 内部可请求下一轮重置，也可在失败分支 CreateMapInAtlas；二者均由协调线程执行。同步 reset 先清 mapper/loop 状态与数据库引用，再沿原顺序处理地图和 Tracking，禁止对同一非递归 mutex 重入。外部用户重置、切数据集不在评估范围内，必须结束本次运行后另起。
5. 跟踪失败仍完成本轮槽及 B。无有效位姿与耗时超限分开记录，不因 reset 重新编号、重新抽样或删除窗口。下一轮为恢复执行的计算纳入该 T；概率假设是否仍适用留给应用步骤 5。异常导致没有完成输出时，记录运行中断和受影响窗口，不能生成伪造的有限服务时间后送入原模型。
6. 固定模式 LC 对象可以保留用于已有指针连接，但不得启动 Run 或 GBA，所有 reset/finish 走同步路径。关闭闭环的异步对照也需要仅数据库维护路径，不能拿有队列泄漏的配置当健康基线。保持默认启用闭环的原生路径；任何对照修复独立说明。

## 5. 每一类等待如何处理

| 等待来源 | 设计处理 | 运行验收 |
|---|---|---|
| 帧释放、上一 B 尚未完成 | 固定图中 max 的等待；独立记录，不计入 S_T | 释放和前驱完成均可关联 |
| mapper/loop/Viewer 竞争 | 固定模式不创建这些 worker；地图只由协调线程写 | 无其他地图写入线程 |
| Frame 左右特征 join | 首版改为顺序提取；OpenCV/Eigen/g2o 内部并行配置限制为一线程或关闭 | 记录构建选项与运行线程；第三方实际行为仍需查验 |
| 交互单步、定位切换、IMU 预积分 | 首轮范围排除，配置/调用拒绝 | 不可悄悄进入等待路径 |
| reset 的轮询 | 同步清理，工作线程模式保留原行为 | 重置、空队列和关闭专项回放不死锁 |
| 坏活动地图轮询 | 固定模式进入前检查/恢复；意外坏地图报异常 | 不等待另一个不存在的写入者 |
| 磁盘读图、日志写盘 | 回放前预加载限定数据；运行时使用预分配记录缓冲，运行后写盘 | 明确是预加载回放；不得报告传感器端到端性能 |
| OS 调度、发布到调用间隙 | 单协调线程减少应用唤醒；独立记录实际开始与就绪时刻的差 | 不把差值塞进服务耗时，不因串行就宣称公式严格成立 |

尤其最后一项仍是 **B4 的实测风险**。令实际开始/结束为 a_T,e_T,a_B,e_B，独立测量服务时间 `S_T=e_T-a_T`、`S_B=e_B-a_B`，并报告

\[
r_T(k)=a_T(k)-\max\{kh,e_B(k-1)\},\quad
r_B(k)=a_B(k)-e_T(k).
\]

所有实际执行的分派、计数与记录代码必须有阶段归属；显式等待不并入 S。普通操作系统不保证 r 恒为零，忙等或 CPU 亲和性也不能构成证明。必须在正式采集前冻结时钟和插桩误差界，逐轨迹用原 g/Phi 检查**累计完成时间误差**；不能只检查每个局部间隙。若出现可分辨的额外等待/抢占，B4 不通过，记录停下；不能通过事后改定义 a、S 或放宽截止来验收。

因此，本设计给出了固定的应用级任务顺序；实际墙钟时序满足模型只可能通过后续测量得到指定精度下的支持，不是当前已证明结论。有限模式联合耗时的三项假设更加不能由该顺序推出。
