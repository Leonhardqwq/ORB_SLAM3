# 固定调度改造的多场景实用性检查

> 后续实用性批次（2026-10-17）：已隔离线程政策和研究对照行为，修复原生 Viewer 退出，并完成扩大后的兼容回归及 18 次质量/资源/时序对照。固定模式仍有原模型时序验收失败；停止概率拟合与预测。 见[最新结果](fixed-usability-results-2026-10-17.md)。下文保留此前检查或首轮实验的历史口径。

2026-10-17。用户新增核心要求：适配原可靠性模型的同时，保持 ORB-SLAM3 在多种自动驾驶算法与场景中的实际应用能力。要求已写入仓库根 `AGENTS.md`。本次只更新约定、审查已有源码及拟议方案；未实现忙等、绑核或新的线程限制，未重跑实验，不改变此前时序验收失败的结论。

## 结论及证据范围

可选执行模式、共享视觉算法和保留原生入口的方向符合要求，但**当前不能验收为已经满足多场景实用性**。现有固定模式只是非惯性针孔双目的首个实现，数据证据来自 EuRoC V1_01_easy 的短段回放；原生兼容性也没有覆盖全部传感器和功能组合。

必须同时满足两项要求：整个 fork 保留既有场景能力；新增固定模式本身在其声明支持的实际场景中有可接受的定位质量和运行成本。仅保留原生模式作为退路，不能代替新增模式的实用性验证。这里的实际角色是视觉/视觉惯性定位与建图组件，不声称 ORB-SLAM3 本身涵盖完整自动驾驶系统。

## 对“睡眠加短时主动检查时钟”的修订

该方案可以作为一个候选等待策略，但**不能直接成为所有入口的强制默认行为**。之前举出的 0.5 ms 只用于说明思路，尚未实现或证明适用于所有平台和频率。

建议把输入驱动、释放等待策略和视觉 T/B 调用分开组织：宿主应用仍可以按原生方式调用，周期驱动可显式选择普通睡眠或睡眠加有限时长主动检查。研究策略不修改图像时间戳，不改计划释放原点，不改变服务耗时定义，不为了通过验收删除慢帧。

- 主动检查默认关闭，启用时明确记录参数；时长设置上限并按周期检查合理性，不把某个 EuRoC 参数写成核心库的通用要求。
- 单次 0.5 ms、周期 50 ms 时，仅这段主动检查的名义时间预算相当于一个逻辑核的 1%；这不是实测 CPU、功耗或额外延迟上界，更不是整机占用率。不同频率和资源竞争下需要重新评估。
- 不自动绑核、提高实时优先级或改变系统调度。必要的平台调优放在显式运行配置中，不把 WSL 专用设置变成通用算法依赖。
- 原生/固定模式共享进程时，线程策略应由应用统一显式决定；避免由库构造函数隐式修改进程级状态，也不能用执行过程中反复切换全局线程数的办法处理并发。独立研究进程可以保留单线程实验配置。
- 普通睡眠策略仍可作为可用配置；若它未满足原模型时序门槛，应明确标为未通过该项模型验收。不能自动切回普通策略后仍宣称原可靠性保证成立。

## 建议的改进与验收顺序（尚未执行）

1. **明确支持范围并检查兼容性。** 建立原生功能和固定模式的覆盖表；首先使用已有数据覆盖原生双目与已有数据支持的惯性/单目路径，其他配置安排可获得的代表数据后验证。源码存在、目标可编译、回放成功和质量合格分别记录。没有证据的项目标未测，不自行宣称保持全部能力。
2. **先限制改动的影响范围。** 将进程级线程政策交由显式应用配置；将研究输入的周期、序列、初始化和缓冲参数从硬编码中分离。先完成这些接口与行为设计，再加入可选的睡眠/主动检查策略。跨线程、关闭、取消和实时输入处理继续有明确规则。
3. **比较时序与实际成本。** 使用冻结参数的原生、固定普通睡眠、固定可选主动检查配置；在空闲与有代表性的共用资源负载下重复运行。保留原 100 微秒模型对应门槛，另外测 CPU 时间/占用、内存、吞吐、定位误差与跟踪失败，不能只用含周期睡眠的总墙钟时间判断 CPU 开销。
4. **扩展代表性场景与使用方式。** 先在固定模式已有支持范围内检查更长序列、运动/纹理差异和跟踪恢复，再验证有界实时输入；其他传感器或闭环等功能扩展需重新审查依赖，不把“整个项目保留功能”写成“固定模式已支持功能”。根据目标用途事先确定可接受的质量和资源退化幅度，不能看完结果再定门槛。

验收需要原生兼容、固定模式的实际质量/成本和原模型对应同时有证据。任何一项失败都分开记录；未通过时序与概率条件前，继续不做真实可靠度认证式表述。当前 B4/B5 的失败记录保留，上述新要求不自动将已有步骤改判成功，也不自动授权本轮开始新实验。
